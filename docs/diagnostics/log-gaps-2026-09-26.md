**Asked by:** the founder, after the 2026-09-26 paste (web `b5f3c92ba13f6984`, native
`2026092602`): *"Maybe good to have an agent or two go figure out what else that error
log should include, seems super useful."*

**Method:** two research passes read the paste line by line, one for the voice engine
(Kokoro probe, native engine) and one for playback in the car (session, route, remote,
report format). Each question the paste could not answer was traced to the code that
dropped the fact. The two passes found 45 gaps. After merging duplicates there are 38 (`L01..L38`).
Of those, 35 are built in three lanes and 3 are deferred, each with a reason. Four partial
ideas are also deferred, again with reasons. The findings also listed 23 existing defects in

**The source paste** (abridged): `engine rows of unknown kinds, not shown: cmd x15`, `MISSING 939 of 1208`,
`sessionActivated (failed)`, `routeChange (unknown)`, `pausedUnexpectedly state=?`,
`voiceProbe … could not measure: synthesis-failed/inference-threw load 457ms/374ms peak 280.3MB`.
Row times are UTC with no date. Page rows `#1009..` and engine rows `#1..#35` share one `#`
numbering. The header has no device, no OS, no power state and no audio route.

## The rules every lane keeps

1. **Local only.** The header line "Local only. Nothing here is sent anywhere." stays
   true. No network send, no analytics, no new upload path.
2. **No precise location or contact data.** Record a route's PORT TYPE, never
   `portName` (a car's or headset's name is often a person's name). Record the hardware
   model identifier (`utsname.machine`, `Build.MODEL`), never `UIDevice.name`, and never
   `identifierForVendor` or any serial. A UTC offset is a time zone, which is coarse
   enough.
3. **Readable aloud.** One line per event, closed vocabularies, and numbers. No error
   `.message` text. `diagnostic-log.js`'s header rule "never a `.message`" and DiagGate
   rules 1-5 still hold. A string outside a closed set is admitted only BY SHAPE, as a
   bare ASCII identifier the way `errorNameOf` admits one, with a cap.
4. **Nothing dropped silently.** A value outside a vocabulary is counted, never stored as
   text (see L33).
5. The header stays phone-width: about 44 characters per line, one fact per line. Rows may
   be long, because they are for pasting.

## Why the lanes split the way they do

`player/diagnostic-log.js` is the ONE renderer for every row, and the lanes must touch
disjoint files. So a field that needs both a native emitter and a JS renderer is split at
a **fixed wire contract** (the tables in each lane below). Each side is tested against
that contract. Any merge order is safe:

- `diagnostic-log.js` TAKES named fields and never spreads them (`voiceProbe()` and
  `sessionEvent()` say so). A new native field is therefore ignored until Lane C
  renders it. It costs nothing and cannot leak.
- Lane C's renderer treats every new field as optional and prints nothing when it is
  absent. Rows from older builds keep rendering exactly as today.
- Engine rows print every field they carry (`engineFields`), so Lane B's new engine
  fields (on `build`, `grace` and `session` rows) show up even before Lane C.
